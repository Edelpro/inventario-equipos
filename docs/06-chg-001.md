## 1. Problema

El starter solo expone `/health`. El inventario no permite registrar equipos, listarlos ni identificar los que requieren reposición, y el usuario no dispone de una interfaz para operar sin herramientas de línea de comandos.

## 2. Solicitud

Conservar RF-01 (crear) y RF-02 (listar) con sus reglas de validación, y añadir RF-03: consulta `GET /productos/stock-bajo` con umbral (predeterminado 5) e interfaz web con umbral inicial 3, errores y salud documentados.

## 3. Análisis de impacto

| EC afectado | Impacto |
|---|---|
| EC-REQ-01 ERS | Pasa de versión 1.0 a 1.1 (RF-03) |
| EC-DIS-01 Diseño | Nuevas rutas, catálogo de errores, interfaz |
| EC-SRC-02, 04, 05, 06 | Enrutamiento, validación, almacén, estáticos |
| EC-UI-01, EC-UI-02 | Nuevos |
| EC-TST-02, 03, 04 | Nuevas pruebas (61 de API y 2 de interfaz) |
| EC-SCR-04 | Nivel de aceptación: salud → api → completa |
| EC-PIP-01, 02 | Sin cambios: los pipelines del starter ya cubren pruebas, imagen y promoción |
| EC-DEP-01, 02 | Sin dependencias nuevas; el bloqueo no cambia |

**Riesgos:** coerción accidental de tipos (`"5"` aceptado como 5), longitud medida en unidades UTF-16 en lugar de puntos de código, confundir la salud con aceptación funcional y suponer que el rollback recupera datos. **Mitigación:** pruebas de frontera y rechazo, verificación posterior al despliegue y declaración explícita de la volatilidad.

**Fuera de alcance (rechazado):** precio, SKU, ventas, inicio de sesión y persistencia. Se documenta el rechazo para no aparentar funciones inexistentes.
